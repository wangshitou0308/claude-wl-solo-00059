# 坡地社区电梯接续引导（跨楼栋）

面向住在**坡地老旧小区**、膝脚耐力各不相同、需要独自前往社区食堂或活动室的中老年住户：
在手机/平板/电脑浏览器上，按“一步一屏”的方式接续换乘楼栋电梯、连廊与坡道，
绕开当日关闭的门禁和超出体力的台阶。

- 前端：React 18 + TypeScript + 原生 SVG（分层图层、可拖拽布点）+ Vite
- 后端：Python FastAPI + SQLite（地图资料与行程进度都存在本机 `backend/data/app.db`）
- 可完全离线在本机运行；前端开发服务器通过 `/api` 代理到后端

## 一、本机运行（两条命令）

需要 Python ≥ 3.10、Node ≥ 18。

```bash
# 后端（首次会自动建库并写入示例小区）
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --port 8765

# 前端（另开一个终端）
cd frontend
npm install
npm run dev
```

打开 <http://localhost:5173>。或在仓库根目录执行 `./run-dev.sh` 一键启动两端。

后端接口文档：<http://localhost:8765/docs>

只跑后端测试：

```bash
cd backend && .venv/bin/python -m pytest tests/ -q
```

## 二、使用流程

### 住户（出行规划页）

1. 选择/在地图点选**出发地**、**目的地**（社区食堂🍚 / 活动室🎲 等）。
2. 填写**出发时刻**、能接受的**连续步行距离**和**楼梯级数**（滑杆）。
3. 系统只在下列条件**同时满足**时给出完整路线：
   - 每台电梯在所经楼层**确实停靠**（老旧电梯只停部分楼层，不停的层不能乘梯）；
   - 到达连廊、门禁、活动室/食堂门时处于**开放时段**（早到会在卡片中明确等待分钟数，
     到晚则该路不可行）；
   - 两次休息（座椅💺或电梯乘坐）之间的步行距离、台阶级数不超过个人上限。
4. 方案按 **楼梯更少 → 最长连续步行更短 → 换乘更少 → 步行更短/更早到** 排序，最多 5 个，
   卡片上标明总台阶、最长连续步行、换乘、等待、到达时刻。
5. 开始引导后进入**一步一屏大卡片**：当前地标 → 下一目标、应乘电梯、**下梯楼层**、
   该梯停靠层、本段台阶/距离、每次等待；地图同步用蓝（待走）/绿（已走）叠加路线，
   红点脉冲显示当前位置。

途中出状况：

- **🚪 门没开 / 电梯坏了**：选择关闭的门或停运电梯，确认当前位置 → 后端把它加入阻断，
  从当前地标重算余程（例如综合楼大门关闭时改走 2 栋↔3 栋空中连廊）。
- **🧭 我走到别处了**：在地图或下拉中确认实际地标，**已走步骤保留**，只重排后面的路。
- **↩ 撤回误点**：任何确认/推进/重算都可逐步撤销。

### 亲友/社区协助者（地图绘制页）

顶部“地图绘制（协助者）”标签下可可视化编辑并**保存到本机 SQLite**：

- **楼栋**：名称、楼层编号（坡地小区支持 0 层、负层、不连续编号）；
- **地标**：楼层平台、门禁/大门、休息座椅（走到即重置连续步行计数）、食堂/活动室；
  直接在 SVG 上**按住节点拖动**布点；
- **连线**：平路 / 无障碍坡道 / 台阶（标注级数，自动画踏步纹）/ 连廊 / 室外步道，
  长度（米）与台阶级数；同一起讫可并存“台阶”和“坡道”两条平行路径；
  可“地图点选两端”快速连边；
- **电梯**：所属楼栋、候梯与每层秒数、**逐楼层勾选停靠节点**（仅停部分楼层）、运行时段；
- **开放/门禁时段**：任意节点、连廊、电梯均可设多个每日时段（如食堂 07:00-13:30、
  16:30-19:00）；编辑器顶部可切换“预览时刻”查看哪些门当前关闭；
- 保存时后端校验引用完整性；“恢复示例”可一键还原内置的三栋坡地小区示例。

## 三、路线引擎要点（`backend/app/routing.py`）

- 时变图上的**多目标 label-setting**搜索，每个节点保留 Pareto 最优标签
  （到达时刻、连续步行、连续台阶、总台阶、总步行、总等待、乘梯次数）。
- 硬约束：连续步行/连续台阶超上限即剪枝；标签携带已访问集合，杜绝无意义的电梯往返绕圈。
- 门/连廊/电梯窗口：早到则等待（写入步骤的 `waits`），当日不再开放则剪枝。
- 电梯边只存在于该梯声明的停靠节点之间，天然表达“只停部分楼层”。
- 输出按楼梯更少、最长连续步行更短、换乘更少排序。

## 四、主要 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/PUT | `/api/map` | 读取 / 保存地图文档 |
| POST | `/api/map/reset` | 恢复示例地图 |
| POST | `/api/routes/plan` | 生成可行路线方案（含约束与排序） |
| POST | `/api/trips` | 按选定方案创建行程 |
| GET | `/api/trips`、`/api/trips/{id}` | 行程列表 / 详情（含完整路线与已完成步骤） |
| POST | `/api/trips/{id}/advance` | 完成当前一步 |
| POST | `/api/trips/{id}/confirm` | 确认实际位置（可带关闭门禁/停运电梯）→ 重算余程 |
| POST | `/api/trips/{id}/undo` | 撤回上一步操作 |

## 五、目录

```
backend/
  app/main.py       FastAPI 路由
  app/routing.py    多目标时变路线引擎
  app/sessions.py   行程：确认位置/重算余程/撤回
  app/models.py     Pydantic 模型
  app/database.py   SQLite（地图 JSON + 行程 JSON）
  app/seed.py       三栋坡地小区示例
  tests/            pytest（引擎约束 + 全流程接口）
frontend/src/
  App.tsx           出行规划 / 行程引导 / 地图绘制 三视图切换
  components/MapCanvas.tsx   分层 SVG（楼栋/连线/电梯/路线/节点/标注）
  components/PlanPage.tsx    填信息、选方案
  components/TripPage.tsx    一步一屏卡片 + 位置确认重算
  components/EditorPage.tsx  协助者绘图
```

数据文件默认在 `backend/data/app.db`，可用环境变量 `APP_DB_PATH` 覆盖。
